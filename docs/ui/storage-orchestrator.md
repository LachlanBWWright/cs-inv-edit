# Storage orchestrator design defence

The storage surface is built around **capacity bars and thematic labels** because storage decisions are operational rather than aesthetic. The first thing the user needs to know is whether a unit has room and what role it plays in the workflow.

The progress indicator is important on both desktop and mobile. Numeric counts alone are slower to interpret, while a bar makes near-full states obvious at a glance.

The storage CTA is again framed as a reservation step. This mirrors the wider UI principle that risky actions should pass through a clear review state before any live write path is considered.
